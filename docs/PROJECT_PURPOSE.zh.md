# Coding4Game_GUI 项目目的

评估 coding agent 能否在真实 Windows 游戏里探索、编程和自测，交付可独立运行的
Python 玩家。记录开发轨迹、实际资源开销、任务成绩和失败证据。当前发布范围是
[15 个正式场景](SUPPORTED_GAMES.md)，每个场景有登记的起点、动作协议和评分规则。

## 实验流程

| 流程 | 约定 |
|---|---|
| 开发 | 真实 Linux Codex 或 Claude Code 在一轮持续的 WSL2 环境内开发、评估并明确选择程序 |
| 独立测试 | 在新的干净 WSL2 环境中重建依赖并运行冻结程序，全程无模型推理 |
| Direct 基线 | 配置的模型根据截图提交分步动作，由宿主计时和结算 |

Windows 宿主负责游戏启动、存档准备、输入、评分、账本、归档和上游凭据。
三条流程使用登记的动作和计时协议。实验进展通过正常游戏输入获得。
在技术可用且经验证时，可以只读游戏状态。开发提示保持方法中立，宿主评估器
内部信息和凭据留在宿主。

## 成功标准

1. 开发 CLI 在适用预算内保存候选，经有效评估后明确选择一个不可变程序归档。
2. 所选程序经过单独启动的无模型测试，程序身份、退出、成绩和资源可核对。
3. 失败、恢复和实际用量可追溯。缺失用量记为未知，游玩中分数保持空值。
4. 比较时公开任务、起点、输入、模型和资源条件，按有效重复的证据解释表现。

优先完成 WSL2 开发、独立测试和 Direct 基线的实验证据。软件回归、真实 CLI、
游戏操作与隔离分别验收。当前隔离资格为 `autonomous_benchmark_eligible=false`。
异步开发 rollout、隔离下的多游戏并行和新增场景范围暂缓。

## 发布与维护

源码以 Apache-2.0 发布。操作从 TUI 进入，批量任务使用通用启动器。新机器先核对
游戏安装、账号、存档、窗口、输入和起点，再验证实机评分。原始游戏、存档和运行
证据由操作者保管。已关闭的合格开发可按原会话与累计资源恢复。

实现细节见[运行契约](README.md#runtime-contracts)，授权、语言与维护约定见
[AGENTS.md](../AGENTS.md)。
